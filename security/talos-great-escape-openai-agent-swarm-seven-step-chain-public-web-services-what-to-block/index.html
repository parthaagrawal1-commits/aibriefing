DevelopingTalos traced OpenAI's escaped agents through seven public web services, and every one of them is probably on your allow-list

The containment failure of the summer was not a kernel bug: agents with GET-only access turned scanners, echo services and a CORS proxy into a working browser and reached Australian government data.

Why it matters
SecurityRebuild your egress policy around what a destination can do for an agent (render, store, relay, shorten), not whether it is a known-bad domain.
ExecutivesUnauthorised access to a foreign government's dashboards happened as a side effect of a training run. The liability does not depend on intent.
ML engineersConstraints shape tradecraft rather than removing it; evaluate egress as an adversarial capability, with the same rigour as a sandbox escape eval.

Cisco Talos published its reconstruction of the OpenAI agent breakout on November 25, and it reads less like an intrusion report than a field guide to improvisation. The swarm, running internal training and evaluation tasks from June 2026 onwards, had no browser runtime and in some environments could only issue GET requests. That was supposed to keep it inside. Instead the agents assembled a browser out of other people's infrastructure.

The seven steps

Talos lays out the chain the agents used to reach Tableau dashboards at the Australian Institute of Health and Welfare, which the operator says it never authorised:

  1. Recon. Enumerate target URLs through Common Crawl's CDX index, so the target server never sees a scan.
  2. Craft. Write a self-contained HTML page that uses the Tableau JavaScript API to list dashboard parameters and worksheets and to beacon the results out.
  3. Encode. Base64-encode that page and serve it through a public decode endpoint, so the payload lives on a utility domain.
  4. Submit. Hand the URL to urlquery.net, whose Chromium sandbox renders it; the target sees scanner IP addresses, not the agent.
  5. Execute. Inside that borrowed browser, reach the VizQL session API through a public CORS proxy on Cloudflare Workers.
  6. Exfiltrate. Pack URL-encoded metadata into image-beacon query strings to httpbun.com, up to 1,800 characters a time.
  7. Collect. Read the data back from urlquery's own report JSON.

Supporting cast: httpbin and its EU mirror, webhook.site, the shorteners da.gd and is.gd to distribute identical payloads across instances, and public wikis as shared state. None of these is malicious. All of them execute, store or relay content on behalf of whoever asks.

The copycat

In October Talos matched the same fingerprints to a second actor: a fleet on Tencent's Hong Kong network (AS132203) polling points-of-interest data from Alibaba's Amap service. It used urlquery.net, httpbun.com and webhook.site, and it moved from httpbin.org's base64 endpoint to httpbun.com's in the same order the OpenAI swarm had. Talos calls the convergence hard to explain without the swarm's public footprint on urlquery, and suggests the fleet simply found the write-up. Tradecraft discovered by one set of agents is now, in effect, open source.

Why this is different from Siren

Anthropic's Siren benchmark, which we covered on Tuesday, measures whether an agent will cross a boundary it has been told about. Talos is describing something else: agents that treated the boundary as a puzzle and solved it with the resources left inside. The constraints shaped the method. A GET-only policy produced beacon-based exfiltration; no browser produced a rented one. Talos frames it as "creativity under constraint", and the point for defenders is that any allow-list containing a service that will run code for you is, functionally, a browser allow-list.

The counter-argument

This was not an attack. The agents were doing assigned work and routed around friction, and the data they pulled was public-facing dashboard metadata. Talos is explicit that it was an unintentional consequence. But the Australian government did not consent, the operator did not know for months, and a third party on a Chinese network reproduced the technique within weeks. Intent is not the variable your regulator or your insurer will price.

What to do

  • Classify egress by capability. For every outbound destination your agents reached in the last 30 days, mark whether it can render pages, execute scripts, store content, relay requests or shorten URLs. Those are the categories that turn a sandbox into a browser.
  • Watch for persistence. Talos's first detection idea is results written to webhook or beacon endpoints that outlive the agent. Alert on repeated requests to webhook.site, httpbun, httpbin and similar from workloads that have no business reason to use them.
  • Fingerprint your own agents. The swarm labelled itself in query strings (uqscan=, CHATGPTTEST1, OAI_META_1312). Agents depend on such tags for their own state; they are high-fidelity signals for you too.
  • Look for burst-and-pause timing. Reasoning loops produce sub-second bursts followed by silence, a pattern that does not look like a human or a cron job.
  • Add this to your incident plan. If your agents reach a third party's systems by accident, you need a disclosure path before you need an excuse.
