OpenAI and Cisco release Shirudo, an open-source eBPF shield for unpatched Linux, as CISA confirms AI agents exploited a MONAI Label zero-day in 11 minutes. What to do with both

The same week that machine-speed exploitation became routine, the first machine-generated mitigation layer arrived under a BSD licence; the gap between the two is now measured in minutes, and your patch window is not.

Why it matters
SecurityAdd CVE-2026-133968 (MONAI Label) and CVE-2026-134624 (N-able MailAssure) to this week's emergency list; CISA's federal deadline is November 26. Then stand up Shirudo in observe mode on one Java host and see whether a generated shield for Java4Shell matches what your patch team did by hand.
DevelopersA shield is a signed eBPF program that intercepts a vulnerable code path, not a code change. It buys time; it does not replace the upgrade, and it can be removed from a TPM-logged record.
ExecutivesAttackers now go from zero-day to root shell in a quarter of an hour with little human involvement. Ask what your organisation's time-to-mitigate is for internet-facing Linux, and whether anyone owns that number.
ML engineersMONAI Label is a medical-imaging annotation server that many research groups expose to the network for convenience. If your lab runs it, it is on the Known Exploited Vulnerabilities list now.

Shirudo, Japanese for shield, is an open-source runtime that OpenAI and Cisco published on Monday for keeping Linux systems protected between the moment a vulnerability is known and the moment a tested patch is rolled out. It uses eBPF, the kernel's sandboxed programmability layer, to watch kernel and network activity and to apply narrow controls on a specific code path. Cisco's Isovalent team built it on the lineage of Tetragon; OpenAI supplied the agentic workflow that investigates a vulnerability and drafts the shield. The code is on GitHub under a BSD 2-Clause licence, with the BPF programs dual-licensed BSD and GPL, and it runs on x86-64, ARM64 and RISC-V.

How a shield works

Four properties matter. A shield loads into a running process without a restart, and operators can watch what it would block before they let it enforce. Shields are generated by an agent but deployed by people, and OpenAI is explicit that security teams keep control of rollout. Every shield is cryptographically signed and verified before load, on top of the kernel's own eBPF verifier. And a TPM records each load and removal, so an auditor can later prove what protection was in place when. Shields ship as signed packages through OCI registries, there is no permanently running daemon, and for cases eBPF cannot reach the tool can also rewrite application bytecode.

The demonstration is the bug this site has covered for a week. Using Codex, the team generated a shield that adds an input check to Java's Base64 decoder, the path behind Java4Shell (CVE-2026-114938), and attached it to a live Elasticsearch 9.5.5 process. The exploit input was rejected; the service never restarted. Both companies describe it as a controlled test, and neither has given Shirudo a version number or called it production-ready. A technical webinar is scheduled for December 15.

The other half of the story

On Monday CISA added two flaws to its Known Exploited Vulnerabilities catalogue with a federal remediation deadline of November 26. CVE-2026-134624, rated 9.3, is a server-side request forgery in N-able MailAssure's LDAP sync check that let an authenticated API user reach internal hosts; N-able has said exploitation was confined to one hosted server during an incident that disrupted Mail Assure and SpamExperts from November 16 to 21. CVE-2026-133968, rated 9.8, is an unauthenticated path traversal in MONAI Label, the open-source medical-imaging annotation server, that allows arbitrary file writes.

The MONAI case is the one to read twice. According to an account attributed to Amazon's chief information security officer, a suspected China-linked actor used an AI engine called CAIRN to run largely autonomous attacks. The agents found and used the MONAI Label flaw against a target in about eleven minutes, later dropped a Python reverse shell into sitecustomize.py, triggered a training endpoint to spawn a process, and obtained a root shell, then pivoted through a proxy into a second university running the same software. It sits alongside ARTEX, AntiFox and CyberStrikeAI in a cluster of AI-driven frameworks now linked to breaches at more than a hundred companies.

The counter-argument

eBPF shields are not new; Isovalent and others have sold runtime enforcement for years, and a wrong shield can break a production service as surely as a bad patch. What is new is the generation step, and an agent that writes a kernel-adjacent program from a CVE description is exactly the kind of component that needs the signing, verification and audit log Shirudo wraps around it. Treat the agent output as untrusted until the observe-mode data says otherwise.

What to do

Patch the two KEV entries first; the deadline is Thursday. If you run MONAI Label anywhere reachable from a campus network, take it off the network until it is fixed. Then pick one internet-facing Java service, install Shirudo from the quickstart, and run the Java4Shell shield in monitor mode for a week. Compare its decisions with your own detection logs. If it never fires on legitimate traffic, you have a template for the next out-of-band bug, and a measured answer to the question of how long your organisation is exposed between disclosure and patch.
