Anthropic's Claude Ship puts an agent on the whole pull request: PR Steward fixes CI, Approvals can merge-approve, and /ship opens the PR. What engineering leads should configure first

Code Review was the easy part; the new beta lets an agent act on the findings and, under a policy file you write, approve routine changes without a human, which makes the policy file the most important code in your repo.

Why it matters
DevelopersType /ship in Claude Code and the agent pushes, opens the PR, reviews it, and keeps fixing checks and review comments until it is green; @claude stop halts it. It cannot merge, and PR Steward comments after every push with a rollback path.
SecurityClaude Approvals reads a natural-language policy from the default branch. That file now decides what reaches main without human eyes, so protect it with CODEOWNERS and require a human review for any change to it.
ExecutivesAnthropic says its own Claude Code team more than doubled merged PRs between June and September with reverts down over 40%. The credit offer (at least $10,000 for Enterprise, claim by January 15) makes a one-repo pilot effectively free.
FinanceReview and Steward bill by tokens with admin spend caps; /ship counts as ordinary Claude Code usage. GA reviews were quoted at $15–25 each in preview, so a busy monorepo can reach five figures a month without the cap.

Anthropic on Monday bundled three GitHub-native capabilities into a beta it calls Claude Ship. Code Review, generally available since October 15, reads a pull request and posts findings. PR Steward, new and in beta, acts on them: it fixes failing CI checks, resolves merge conflicts, responds to reviewer comments, and after every push leaves a comment explaining what changed and how to roll it back. Claude Approvals, also beta, applies an approval policy written in plain language and stored in the repository, and can approve routine changes or escalate them to named humans. A new /ship command in the Claude Code CLI and desktop app chains the lot: push, open the PR, review, iterate until checks pass.

Availability is Claude Team and Enterprise on GitHub repositories only. Organisations with zero-data-retention, HIPAA or customer-managed-key configurations are excluded for now. Review and Steward are billed on token usage under admin-set monthly limits; /ship counts toward normal Claude Code usage. Eligible Enterprise customers can claim at least $10,000 of Claude Ship credits until January 15, 2027.

The boundaries Anthropic drew

PR Steward cannot approve or merge. Claude Approvals can approve, but only within the policy file, which takes effect once it is on the default branch, and GitHub branch protection still applies on top. Anthropic recommends starting in observe-only mode on a single repository with a spend limit, and says the policy can take Code Review findings and custom classifiers as inputs. A developer steers the agent with @claude in PR comments and stops it with @claude stop. Anthropic's internal evidence is that merged pull requests on the Claude Code team more than doubled from June to September while the share of reverted PRs fell by more than 40%; the company quotes itself, so treat it as a vendor claim.

Why the policy file is the real product

This is the first mainstream release in which an agent's output can satisfy a required review on a protected branch. In GitHub's model, a required approval is a security control; CODEOWNERS and branch protection exist to keep a single compromised account from shipping code alone. A natural-language policy that auto-approves, say, dependency bumps and documentation changes is reasonable. The same file with a loosely worded clause is a path from a prompt injection in a PR description to an approved merge. The site's security coverage of the last fortnight, the Microsoft Agent Framework PyPI poisoning and the Together AI credential leak, both started with an agent doing something plausible inside a repository.

The counter-argument

Teams already run auto-merge for Dependabot and have for years; the novelty is scope, not kind. And the alternative to agent approval is review queues that stretch for days while agents write most of the code, which is the situation Anthropic says it was in. The question is not whether to allow it but what is routine enough to allow.

What to do

Enable Code Review only for the first two weeks and measure how many findings reviewers act on. Add PR Steward on one repository with a monthly cap and watch the rollback comments; they are the audit trail. Before you turn on Approvals, put the policy file under CODEOWNERS, require two human reviews for changes to it, keep the GitHub rule that a human approval is still required on anything touching auth, payments or infrastructure, and run observe-only mode until you can list what the agent would have approved and agree with every line. Then expand by file path, not by repository.
