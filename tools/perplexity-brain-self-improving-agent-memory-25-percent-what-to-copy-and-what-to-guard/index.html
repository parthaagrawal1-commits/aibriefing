Perplexity's Brain: an agent memory that records its own work and rewrites its skills overnight, with correctness up 25% on repeat tasks. What to copy, and what to guard

Memory about the user is old news; memory about what the agent did, what failed and what was corrected is the new layer, and it is also a new place for bad instructions to persist.

Why it matters
DevelopersThe traceable, incrementally updated LLM wiki loaded into the sandbox is the reusable design. If you maintain SKILL.md files by hand, this is what the automated version looks like.
SecurityA memory that turns yesterday's session into tomorrow's standing instruction is an injection sink. Require review or signing of memory entries before they load, and keep a diff log.
ML engineersGains are reported on repeated tasks only. Build an eval that separates seen from unseen tasks before you claim improvement, and watch for drift toward last week's workload.

Perplexity has added a memory layer called Brain to its Computer agent, available as a research preview to Max and Enterprise Max subscribers. The design inverts the usual meaning of agent memory. Rather than storing facts about the user, their preferences, contacts and projects, Brain stores a record of the work itself: what the agent did on each task, what succeeded, what failed and what the user corrected. It builds that record into a context graph, reviews it at set intervals, typically overnight, and uses the review to update the skills and context the agent loads the next time it runs. The updated material lives in what Perplexity calls an LLM wiki, loaded automatically into the agent's sandbox and revised incrementally, and every entry links back to the session, file or source it was derived from.

The numbers

Perplexity reports early measurements rather than a benchmark: answer correctness up 25% on tasks the agent has encountered before, recall up 16%, and the cost of tasks that need historical context down 13%, because the agent no longer re-derives what it already learned. All three are internal figures with no published test set, and all three are scoped to repeated work. Nothing is claimed for tasks the agent has never seen, which is the honest boundary of the approach: a memory of past work helps when the future resembles the past.

Why it matters

Agent skills, the reusable instruction files that tell a model how to carry out a class of task, have become the main way teams encode process knowledge, and they are maintained by hand. Someone notices the agent keeps mishandling an expense-report format, edits the skill, and hopes the edit generalises. Brain automates that loop and, importantly, keeps the provenance of each change. That second part is what separates a usable system from a black box: when the agent's behaviour shifts, a reviewer can trace the new rule back to the session that produced it. The economics follow. If a meaningful share of enterprise agent work is repetitive, a 13% cost reduction on context-heavy tasks compounds across a workforce of agents, and the correctness gain reduces the human review that currently dominates the real cost of agent deployments.

The risk

A self-editing instruction layer is also a self-persisting attack surface. Indirect prompt injection today has to succeed in the session where the poisoned document is read. With an overnight review that converts observed sessions into standing skills, a malicious instruction encountered on Monday can become part of the agent's default behaviour on Tuesday, and it will carry a plausible provenance link because it did come from a real session. Perplexity's traceability helps detection; it does not prevent the write. The second risk is quieter: an agent that optimises for last week's tasks can drift away from the general behaviour the vendor shipped, and the drift is invisible unless you evaluate on held-out tasks. Google's GTIG report this week described a backdoor delivered through an agent's settings file; a memory layer is a richer version of the same target.

What to do

If you build agents, copy the architecture, not the claim: a work log with provenance, a scheduled review that proposes skill edits, and a human or policy gate between proposal and load. Keep memory entries in version control and diff them, treat the review job's output as untrusted input, and ban it from writing anything that grants permissions or changes tool access. If you buy agents, ask vendors three questions: can I see and approve what the agent learned overnight, can I roll a memory back, and are gains measured on tasks the agent has not seen. If you are a security team, add agent memory stores to the list of places you look for persistence; the CISO agent checklist on this site has a control for configuration files, and memory is the same control.

What to watch

Whether Perplexity publishes an evaluation with a held-out set, whether memory entries get a signing or approval step before they load, and how quickly OpenAI, Anthropic and Google ship equivalents; all three have skills systems and none has yet described one that rewrites them unattended.

Key terms in this story

  • Indirect prompt injection An attack in which malicious instructions are hidden in content the model reads (a web page, email, document or tool result) rather than typed by the user.
  • Prompt injection An attack in which text the model reads, such as a web page or email, contains instructions that hijack its behaviour.
  • Evaluation (eval) A test set with known-good answers used to measure a model or system on your own tasks.
  • Perplexity A measure of how surprised a model is by text it has not seen; lower means better next-token prediction.
  • Benchmark A standard test used to compare models, such as a set of coding tasks or exam questions.
