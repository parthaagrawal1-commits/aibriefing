macOS 27.3 tightens Full Disk Access because of AI agents: silent denials, no one-click toggle, and a 'Private Folders' permission in the code. What agent developers should do before December

Apple is removing the shortcut that let an assistant app earn blanket access to Mail, Messages and backups with a single switch, and the scoped alternative is not ready; onboarding flows that depend on the old path break next month.

Why it matters
DevelopersIf your Mac agent's onboarding ends with 'flip the toggle for our app', that toggle will not appear in 27.3. Build a drag-the-app-into-Settings flow now and architect for a per-folder permission later.
SecurityDenied probes of protected paths are logged but not surfaced. Endpoint tooling can turn that log into an alert when an agent reaches for data it was never granted.
ExecutivesThe platform owner is deciding how much of a user's data an assistant gets, and the answer is 'what the user explicitly hands over.' Expect the same pressure on Windows and in browsers.

Apple's macOS 27.3 has been in developer beta since November 2 and is expected to ship in December. Its most consequential change for anyone building an AI assistant on the Mac is not a feature but a removal: the shortcut that let an app obtain Full Disk Access with a single switch is going away, and Apple has said in as many words that AI agents are the reason.

What Full Disk Access is and what changes

Full Disk Access is the permission that unlocks the parts of macOS the sandbox normally hides: the Mail and Messages databases, Safari data, Time Machine backups and some administrative settings. Until now, when an app tried to read a protected file without the permission, macOS denied the request and added the app to the Full Disk Access list in System Settings, so a user could enable it with one toggle. Installers for assistant apps have leaned on that path: try to read the iMessage database, fail, tell the user to flip the switch.

Code in the 27.3 beta, examined and published by the developer known as pdfu on November 7, shows the attempt is still denied and is logged, but the app is no longer added to the list. The user has to open System Settings, Privacy and Security, Full Disk Access, and add the app by hand, by dragging it in or using the plus button. Apple's October 2 developer post set the principle: users who want to grant this level of access "can only do so with very explicit user action," because "the risks associated with this level of access will grow substantially" as agents become more capable and autonomous.

The same code references a "Private Folders" permission that would grant access folder by folder or database by database, the obvious answer to the assistant that only wants your messages. It is not functional in the current beta and Apple has not confirmed it will ship. Monday's beta 2 is reported to add warnings and controls over what AI automation apps can see and do; Apple has published no release notes describing them, so treat the specifics as unconfirmed until it does.

Why Apple is doing this

The demand driving Full Disk Access requests is iMessage. Assistants that read your texts can draft replies, summarise threads and schedule from them, and there is no narrower permission that gets them there, so they ask for everything. 9to5Mac's Michael Burkhardt makes the fair criticism that removing the toggle does not solve that: a user who wants the feature will still grant blanket access, with more friction and the same exposure. The scoped permission is the real fix, and it is the part that is not ready.

Apple's calculation is visible in the sequencing. Make blanket access harder first, so the number of apps holding it stops growing; ship the scoped permission when it works; then, presumably, tighten further. The Mac is also the machine where third-party agents from OpenAI, Anthropic, Meta and the coding-tool vendors run with the most autonomy, which makes it the right place to draw the line before the pattern spreads to iOS.

What to do

If you ship a Mac agent, test onboarding on 27.3 beta today. Replace "flip the toggle" instructions with a guided drag-into-Settings flow and screenshots, and expect conversion to fall. Separate features that need Messages or Mail from those that do not, so a user who declines blanket access still gets a working product. Design your data model around folder-scoped access now, because when Private Folders ships, the apps that ask for one database will be the ones Apple features and the ones that ask for everything will be the ones it warns about. If you run a fleet of Macs, add the new denial log to your endpoint monitoring: an agent that probes protected paths it was never granted is telling you something. And whichever platform you build for, read Apple's wording as the industry's next default: an assistant gets what the user explicitly hands over, nothing more.
