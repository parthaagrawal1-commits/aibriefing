Prompt caching: how to cut your API bill by half or more, what each vendor charges for it, and the three mistakes that make it cost more

Every major API now charges a fraction of the input price for tokens it has seen before. Used well, caching cuts 40-90% off the input side of a bill; used badly, it adds a write premium you never recover. Here is how it works at Anthropic, OpenAI, Google and Z.ai as of late November 2026, with the numbers from our pricing tracker.

Updated 2026-11-28 · For: Developers Finance Executives ML engineers

Most of what an application sends to a language model is the same every time. The system prompt, the tool definitions, the policy document, the codebase, the forty previous turns of a conversation: all of it is re-sent with each request, and until 2024 every vendor billed every token of it at full price. Prompt caching changes that. The vendor keeps the processed form of a prefix you have sent before, and when the next request starts with the same prefix it charges you a reduced rate for the part it already has.

The mechanism matters for what you can cache. A model processes a prompt left to right, so a cache hit requires the beginning of the new request to match the cached one byte for byte. Put the stable material first and the variable material last. A timestamp in your system prompt, a user name before the policy text, or tool definitions that reorder themselves will defeat the cache every time.

What each vendor charges

All figures are per million tokens from our API pricing tracker, verified on the vendor pages on November 28, 2026.

Anthropic. Cache reads cost 2.5% of the input price on current models: Claude Fable 5.2 is $8 input and $0.20 cached, Sonnet 5.5 $2 and $0.10, Opus 5.5 $4 and $0.20. Writing to the cache costs more than a normal input token: $10 for a five-minute cache and $16 for a one-hour cache on Fable 5.2, so 1.25x and 2x. The cache is explicit; you mark breakpoints in the request. Older models (Opus 5 and earlier, Fable 5) charge 10% for reads.

OpenAI. Cached reads are 5% of input on the GPT-6.2 models: $0.40 on Astra's $8, $0.10 on Sol's $2. Cache writes are 1.25x input for a 30-minute cache and 2.5x for a 12-hour one. Caching is automatic for prompts above a minimum length; you do not mark anything, which is convenient and means you must check the usage field to know whether it worked.

Google. Gemini 3.1 Pro Preview charges 10% for cached reads ($0.20 on $2 input) plus a storage fee of $4.50 per million tokens per hour that the cache exists; Flash-class models charge $1 per million tokens per hour. The storage fee is the part people miss: a 500,000-token cache kept warm all day costs $54 before you send a single request.

Z.ai. GLM-5.3 lists cached input at $0.26 against $1.40, about 19%, with cache storage marked 'limited-time free'. Cheap models have less to save; a 19% rate on $1.40 is still $0.26, which is more than Anthropic charges on an $8 model.

Where the savings come from

Take a support agent with a 30,000-token system prompt and tool set, answering 10,000 conversations a day of ten turns each, on a $2-input model. Without caching the prefix alone costs 30,000 × 100,000 requests × $2 per million = $6,000 a day. With Anthropic-style caching at 2.5% and one write per conversation, the figure is about $150 for reads plus $750 for writes, under $1,000. The output side of the bill is untouched, which is why caching matters most for applications with long inputs and short outputs: retrieval, classification, agents that read a lot and act briefly.

The three mistakes

  1. Paying the write premium without the reads. A five-minute cache on Anthropic costs 1.25x to write. If the next request arrives six minutes later you have paid the premium and get no discount. Measure your inter-request gap before choosing a TTL; the one-hour tier at 2x pays off only after the second hit.
  2. Breaking the prefix. Anything variable before the stable material invalidates everything after it. Audit the first thousand tokens of your requests for dates, IDs, randomised tool order or per-user text.
  3. Forgetting storage. On Google the clock runs whether or not you send requests. Create explicit caches for bursts and delete them; do not leave a million-token document cached over a weekend.

What to do this week

  • Pull your usage logs and split input tokens into cached and uncached. If cached is under 50% on a conversational product, the prefix is broken somewhere.
  • Move every stable block to the front of the prompt and pin tool definitions in a fixed order.
  • Set the TTL from measured traffic, not from the default.
  • Re-check the rates monthly. OpenAI cut cached reads to 5% at the GPT-6.2 launch and Anthropic to 2.5% with Fable 5.1; the discount has been getting deeper, and the tracker shows the dates.

Common questions

Does caching change the model's answers?

No. The cache stores the model's internal processing of a prefix, not any output. A cached request produces the same distribution of answers as an uncached one with the same text.

Is cached data shared between customers or used for training?

Caches are scoped to your organisation or API key and expire on their TTL. Vendors state that cached content is subject to the same retention and training terms as the rest of the request; if you have a zero-data-retention agreement, check that it covers cache storage explicitly.

Why is the cache write more expensive than a normal token?

The vendor has to process the prefix and then keep its state resident in fast memory for the TTL. The premium pays for the storage; the discount on reads is where the saving comes from, so a cache that is written once and read many times is the goal.
